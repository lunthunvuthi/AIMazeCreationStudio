## Decisions & conventions
- **Node/Express, not the Python backend** — user's explicit choice via
  `AskUserQuestion`. Don't relitigate.
- **The service does NOT spawn its own frontend dev server.** Unlike the CLI spike
  (`render_via_browser.mjs`, which is self-contained and spawns+kills its own
  `npm run dev`), the real service assumes the developer's own `npm run dev` is
  already running (the same instance serving the dashboard being clicked on) and
  just points Playwright at it via `FRONTEND_URL`. Spawning a second Vite instance
  would collide on the port. Fails fast (~2s check, `503`) if unreachable, rather
  than blocking a request for 30s like the CLI script's poll loop.
- **Download reuses Preview's cached blob** rather than calling the render endpoint
  a second time — the enabling gate (`previewedSnapshot === JSON.stringify(current)`)
  already guarantees the cached blob matches current state.
- **The CLI script (`render_via_browser.mjs`) is left as-is**, small duplication of
  the ~15-line render logic between it and `pdf-service/render.js` accepted
  deliberately — the CLI script's separate throwaway-spike dependency graph
  shouldn't get coupled to new production infra for two call sites.
- **`/spike/pdf-preview` route is still used as-is** by the real service (not
  renamed/promoted out of `src/spike/`) — kept the diff scoped; a rename is a
  reasonable future cleanup, not done here.
- Answer-key PDF generation exists in the service (`?answerKey=true`) but **no
  frontend button calls it yet** — out of scope per the dashboard's §6.1 button
  contract (Save Progress / Preview / Download only). Fast-follow if wanted.

## Gotchas / watch-outs
- **Vite's `server.proxy` forwards the original request path unchanged — it does
  NOT strip the matched prefix.** A request to `/api/pdf/render` gets proxied to
  `http://127.0.0.1:8010/api/pdf/render`, not `.../render/pdf`. The Express route
  had to be registered at the full `/api/pdf/render` path for this reason — this
  matches the existing FastAPI backend's own convention (`/api/maze/*` routes are
  registered under that full path too). If adding more pdf-service routes, register
  them under `/api/pdf/...`, not a shorter path.
- Running the full stack for manual testing needs **three** processes: FastAPI
  backend (`:8000`), frontend dev server (`:5173`), and `pdf-service` (`:8010`) — in
  that order doesn't matter, but pdf-service requests will `503` until the frontend
  dev server is up.
- `Web App/pdf-service/node_modules` is covered by the root `.gitignore`'s
  `node_modules/` rule — confirmed via `git check-ignore -v`, no per-directory
  `.gitignore` was needed.
