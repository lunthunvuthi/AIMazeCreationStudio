## Decisions & conventions
- `LevelProgress` schema changes apply uniformly to kinder/primary/advanced — no
  per-level special-casing in the data model.
- Sheet metadata is edited on the **Level Dashboard**, not at the "Choose a level" step.
- Re-rating or removing a slot that already has a maze is destructive and gated behind
  `window.confirm` (no existing custom-modal pattern in this codebase to reuse instead).
- `difficulty_setting.md`'s per-level star counts are now framed as **defaults**, not
  enforced totals — confirmed as an intentional design shift this session, not a
  temporary hack.
- `[[feedback_spec_conflicts]]` (standing memory: ask before editing a design doc's
  numeric constants): respected this session — the actual distribution numbers and
  `starParams` values in `difficulty_setting.md` / `starParams.ts` were **not**
  touched, only surrounding explanatory text.

## Gotchas / watch-outs
- `QuestionSlotCard` used to be one giant `<Link>` wrapping the whole card; it no longer
  is. Any future change to this component should keep the difficulty `<select>` /
  Remove button **outside** the `<Link>` (siblings, not nested) — nesting interactive
  controls inside an `<a>` is what the restructure was specifically avoiding.
- `setQuestionStar`/`addQuestion` recompute `question_id` occurrence numbers by
  counting current siblings with the same star — this is a heuristic, not a strict
  global counter, so IDs are stable in practice but not guaranteed unique across
  every conceivable add/remove/re-rate sequence (edge case, not hit in testing so far
  since no UI testing was done — see Next step).
- Dev servers were **left running throughout, not restarted** (uvicorn :8000, vite
  :5173) — confirmed still responding via `curl` at the end of this session, but the
  new UI has not actually been clicked through in a browser yet.
