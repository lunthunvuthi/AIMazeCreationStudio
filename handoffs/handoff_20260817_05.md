   walls**, not the raw cell-by-cell route — two routes breaking the same walls but wandering
   differently through open cells are now the *same* solution. Updated `rules.md` §6 and

## Decisions & conventions
- **Uniqueness = distinct broken-wall-set, not distinct cell route** (`rules.md` §6, confirmed
  by the user this session). Don't reintroduce raw-path counting.
- **S/G cells can now own walls** (`s|`, `g_`, etc. are valid tokens) — confirmed by the user
  this session, extending the format from what shipped in `handoff_20260817_04.md`. The
  wizard's Step 4 no longer restricts which edges are clickable.
- **Star-8 generation costing ~6-10s is an accepted trade-off**, not a bug to chase further —
  the user explicitly declined the bigger biconnected-component fix after seeing it wouldn't
  even apply to real mazes. Don't re-attempt free-region collapsing without a fundamentally
  different (bridge-finding) approach, and don't "fix" the timing by loosening
  `max_states`/reverting the dedup rule.
- **Wizard stepper**: jumping is bounded by `maxReachedStep` (highest step index reached via
  Next) — never allow jumping past an unreached step, even though visited/completed steps are
  freely revisitable. This was a deliberate safety choice to avoid crashing later steps that
  assume earlier data exists.
- Both algorithm changes this session (format extension, uniqueness redefinition) went through
  explicit `EnterPlanMode` + user confirmation before touching `rules.md`/`validator_design.md`
  — per `[[feedback_spec_conflicts]]` (existing memory): don't silently edit design docs.
