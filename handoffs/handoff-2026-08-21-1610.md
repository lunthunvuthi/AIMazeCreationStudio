### 1. Cover page — `spike/CoverPage.tsx` (new)
Built on the owner's four-part breakdown: header / title band / body watermark /
Direction box. `Front Cover.svg` is used **byte-for-byte unedited**.

- **Layer trick that makes it work.** The owner's requirement was "part 4 always on top,
  hiding some of the watermark." Rather than compositing into the SVG, the watermark is
  drawn *underneath the whole template*, and the template's own opaque white header rect,
  opaque Direction-box fill and gray title band do the masking. No clip paths, no edits to
  the designer's file — a redraw drops in and masking still works. **Do not "improve" this
  into layered compositing.**
- **1 SVG user unit == 1 CSS pt.** The template's viewBox is A4 at 72pt/in, so with the
  page wrapper at exactly `210mm x 297mm` every offset is read straight off the designer's
  path data as `pt`. No conversion math anywhere. Measured region table added to
  `pdf_design_spec.md` §12.2.
- Header level + month/week text substituted from real `LevelProgress`. `patchTemplate`
  **throws** if either field can't be found, so a reshaped template fails the export
  instead of printing "Kinder" on a Primary sheet.
- Class names (`.cls-1`…`.cls-16`) and the `clippath` id are namespaced on load — an
  inline `<svg>`'s `<style>` is document-global and would otherwise leak onto question
  pages.

## Gotchas / watch-outs
- **`npx tsc --noEmit` in `Web App/frontend` typechecks ZERO files** and always exits 0 —
  the root `tsconfig.json` is references-only (`"files": []`). Prior sessions cited it as
  proof; it proves nothing. **The real check is `npm run build` / `npx tsc -b`.** A warning
  comment is now in that tsconfig.
- Related TS trap: a component handler closing over a value narrowed by an early return
  **must be a `const` arrow, not a hoisted `function` declaration** — hoisted declarations
  are treated as created before the narrowing. That was the exact `npm run build` break.
- **Do not "simplify" the `@font-face` rules.** Roboto v51 is a *variable* font (one file,
  hence `font-weight: 100 900`), and families literally named `Roboto-Bold` /
  `Roboto-Medium` are declared on purpose: the SVG sets `font-family: 'Roboto-Bold',
  Roboto` with **no font-weight**, so without them that text matches `Roboto`@400 and
  renders regular where the design wants bold. Verified by measurement: `Roboto-Bold` and
  `Roboto`@700 both render 355.73px; `Roboto`@400 renders 350.97px.
- **The watermark is the only panel in the document with no frame** — looks like an
  inconsistency if you don't know why. Reason is in `WallGrid`'s prop doc and
  `pdf_design_spec.md` §12.2. Don't "restore consistency."
- **PDF grew ~284KB -> ~729KB** after the sRGB conversion, and that's expected: Chromium
  now embeds the JPEG **verbatim** (`/Filter /DCTDecode`) instead of decoding and
  re-encoding it to Flate. Better fidelity. The only size lever now is the source JPEG's
  own quality.
- **Stale in the app, tracked as a follow-up:** `LevelDashboardPage.tsx` still renders row
  0 as a locked "Cover / Tutorial" card and `levelStore.startNewLevel` still reserves
  `pages[0]`. Both are now wrong — the cover consumes no question. Flagged inline in
  `level_dashboard_pagination_spec.md` and `PRODUCTION_PROCESS.md` §4.
- Running the stack for manual testing still needs three processes: FastAPI `:8000`,
  frontend dev `:5173`, pdf-service `:8010`. pdf-service `503`s fast until the frontend
  dev server is up.
- One pre-existing, unrelated lint warning in `spike/pdfMazeTypeRegistry.tsx:71`.
