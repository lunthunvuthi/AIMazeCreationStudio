## Decisions & conventions
- **BRANCH AND PR FOR EVERYTHING. Never commit or push to `main`.** (CLAUDE.md.) Followed.
- **Do not stack PRs on other PRs again.** PR #6 was based on `phase-b-advanced-run`.
  #5 merged that branch to `main` first, so #6 then merged into its *stacked base*, not
  into `main` — stranding both scripts one branch short. PR #7 existed only to land them.
  Branch from `main`, or retarget to `main` as soon as the parent merges.
- **Mazes are generated then replayed click by click through the real UI.** The wizard is
  under test, not maze design — and since a generated maze is already known-unique, a
  faithful replay *must* end in a green Validate. Anything else means the wizard and the
  generator disagree. Do not "simplify" this into direct store writes.
- **Driver and verifier are split along their dependencies**, not by phase: the driver
  knows how to click (Node/Playwright), the verifier knows how to read a PDF
  (Python/PyMuPDF). Deliberate — neither drags in the other's toolchain.
- **Playwright is borrowed from `pdf-service`'s `node_modules`** rather than installed at
  the repo root, to avoid a second Chromium download.
- **§5's Advanced-last-page gap stays OPEN**, not closed. The run proved it is not a risk;
  the artwork is still genuinely owed.
- Carried from before, still deliberate: Preview's `allComplete` gate was chosen **over**
  building a placeholder panel (that route is still open, documented in
  `level_dashboard_pagination_spec.md` §6.1); Answer Key deliberately does **not** use
  Preview/Download's blob-cache + snapshot gate; `@dnd-kit/sortable` is NOT installed;

## Gotchas / watch-outs
- **The app needs THREE processes.** backend `:8000`, Vite, pdf-service `:8010`.
- **pdf-service defaults to `FRONTEND_URL=http://localhost:5173`.** If Vite moved to 5174,
  pdf-service still renders against whatever stale server holds 5173. The driver's
  `--frontend` points **the driver only** — it does not fix pdf-service.
- **A stale Vite from an older session holds `:5173` (pid 53501).** Left alone
  deliberately across three sessions now. All runs this session used `:5174`.
- **`npx tsc --noEmit` in `Web App/frontend` typechecks ZERO files.** Use `npm run build`.
- **`scripts/run_backend.py` dies under `nohup … &`** (terminal watchdog, by design). It
  works fine as a persistent background task; this session used `--no-reload`.
- **Playwright's `locator.count()` does not auto-wait.** The wizard renders nothing until
  its draft effect runs, so probing early returns 0 and silently skips a step. Cost one
  run. Documented in the driver's header.
- **Preview's blob tab is a *download* in headless Chromium**, not a viewer tab. Never wait
  on download counts. Documented in the driver's header.
- **Changing a slot's Difficulty renames its `question_id`** and discards the authored
  maze — but this **is guarded**; `handleChangeStar` confirms first. Reported as a bug in a
  previous session; that report was wrong.
- A new level is seeded with its full slate of empty slots; "Add question" only appears on
  rows holding one question.
- One pre-existing, unrelated lint warning in `spike/pdfMazeTypeRegistry.tsx:85`.
- Still no test runner in the frontend. Verification is browser-driven via these scripts.
