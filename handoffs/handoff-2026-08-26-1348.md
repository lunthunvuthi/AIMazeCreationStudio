## Decisions & conventions
- **BRANCH AND PR FOR EVERYTHING. Never commit or push straight to `main`.** Set by the
  owner this session, after `441b02c` and `431e729` went direct. Written into `CLAUDE.md`
  (PR #2) and into memory as `feedback_branch_and_pr_always`.
  **A request phrased "commit and push" does not override this** — that exact phrasing is
  what caused the mistake. Read it as "land this change", and land it via a PR.
- **Those two direct commits stay on `main`.** The owner was offered a rewind + force-push
  to retrofit a PR and **declined** — force-pushing a published branch is worse than the
  convenience. Don't try to clean them up later.
- **`@dnd-kit/sortable` is deliberately NOT installed**, resolving §5.2's open "if the
  semantics map cleanly". They don't: gesture 1 is a *swap*, and sortable does
  insert-and-shift (a cross-row drop would push a question out of the target row instead of
  exchanging with it); and two of the three drop targets aren't list items at all (a row's
  free slot, and the sheet-level "+ Add new page"). Revisit **only** if §5.1's whole-row
  reordering is ever wanted — that one genuinely is a list reorder.
- **Cards drag by a grip, not their whole surface.** The card wraps a Link to the wizard, a
  difficulty `<select>` and a Remove button; a card-wide activator would put a
  pointer-capturing listener over all three. The grip also gives the keyboard sensor a
  focusable element, which is what makes every gesture pointer-free.
- **Every DnD guard lives in the store, not `handleDragEnd`**, which only routes. So a drag
  and the equivalent click-driven edit cannot diverge.
- **No-op drops are refused, not ignored**, and their targets are passed `disabled`.
- **`isBonus` does not travel with a question** — it's a property of the page (§4.4).
- **`concept.md` leaves three questions unanswered on purpose** (its §7). They are the
  owner's to answer; don't guess them in a later pass.

## Gotchas / watch-outs
- **`npx tsc --noEmit` in `Web App/frontend` typechecks ZERO files.** Use `npm run build`.
  Still the easiest way to waste an hour. Now also in `CLAUDE.md`.
- **A question card is its own drop target** — that's how the swap works. Consequence:
  anything reacting to "over" state must special-case `over.id === active.id`, or it fires
  the instant the card is picked up. That's exactly the announcement bug fixed this session.
- **dnd-kit's PointerSensor here has a 5px activation distance**, deliberately: a
  pointerdown that never moves has to stay a click, because the card body is a Link. Any
  Playwright drag must therefore start with a small move *before* travelling to the target,
  or nothing activates.
- **Playwright drags need the whole sheet on screen.** A first test run failed only because
  the "+ Add new page" button was below a 1400px-tall viewport, so the pointer never
  reached it. 2400px fixes it. The failure looked exactly like a broken gesture — it wasn't.
- **`outline-2 outline-dashed`** (the armed-drop-zone hint) is a Tailwind **v4** utility;
  `ring-dashed` does not exist. Verified present in the built CSS.
- The frontend has **no test runner installed**. The store tests this session were run by
  bundling a scratchpad harness with `npx esbuild` and running it in Node. That harness is
  in the scratchpad, i.e. **not preserved** — re-derive it if needed.
- One pre-existing, unrelated lint warning in `spike/pdfMazeTypeRegistry.tsx:85`.
- Still true, still deliberate: the solution path is dark grey `#58595B`, **not** the ink
  black `pdf_design_spec.md` §0 measured. Don't "correct" it.
